# 0.6.1 — 2026-11-12

## Added

- **`hn_search_content` `minComments` filter**: an integer ≥ 0, sent to Algolia as `num_comments>=N`. It applies to stories and polls and is rejected with `tags: "comment"` or `"job"` as `min_comments_unscored_type`. (#54)
- **`hn_search_content` comment hits carry `parentId` and `storyUrl`**: the id of the item the comment replies to (read it with `hn_get_thread`), and the link its story submitted, absent for a text post. (#53)
- **`User-Agent` on every Firebase and Algolia request**: `hn-mcp-server/<version> (+https://github.com/cyanheads/hn-mcp-server)`.

## Changed

- **`hn_get_user` notice for an empty final window**: a window whose submissions are all dead, deleted, or absent now says so, with its `submissionOffset` and `total`.
- **`hn-guide` skill 1.1**: corrects the hiring-thread posting dates and adds `minComments` guidance.
- **Framework adoption** (mcp-ts-core 0.13.19–0.13.22): Bun ≥1.4.4 is required; `initialize`'s `serverInfo` carries `description`; a rate-limit error's trailer adds `retry after <value>`; installed as a project dependency, the server resolves its own `skills/` and logs directory; the `.mcpb` bundle no longer ships dependency-root `AGENTS.md` and `CLAUDE.md`. `framework-skills/`, `scripts/`, and `changelog/template.md` are resynced.

## Fixed

- **A stories or user page on which every item failed throws its dominant cause** instead of the first slot's error: a rate limit first, otherwise the most frequent declared upstream reason. When no answer from the HN API is the most common failure, it throws the new `upstream_no_response` (`Timeout`, with `data.itemCount` and `data.budgetCut`), declared on `hn_get_stories` and `hn_get_user`. (#51)
- **`retry_deadline_exceeded` is declared** in `errors[]` on `hn_get_stories`, `hn_get_user`, and `hn_get_thread`.
